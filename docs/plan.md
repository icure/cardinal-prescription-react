# Implementation plan: country-configurable medication architecture

This records the decisions from the `grill-me-for-prd` session published as
[PRD #3](https://github.com/icure/cardinal-prescription-react/issues/3), refined by what's now
known now that the `medINDEX` TypeScript SDK (`@icure/medindex-sdk`, a separate repo at
`../medindex-sdk`) has actually been built. See `CONTEXT.md` for the domain vocabulary used
below (`MedicationProvider`, `regulatory` bag, `regulatory badge renderer`, ...) and PRD #3 for
the full BE-vs-FR gap analysis and user stories — not duplicated here.

## Why this plan exists

This repo is hardwired to Belgium: medication lookup goes through SAM, prescription sending
through recip-e, and Belgian identifiers (SSIN, NIHII, CNK, RID) are baked into its types with
no country abstraction anywhere. PRD #3 designed a `MedicationProvider` abstraction so this
package can also source medications from Switzerland's medINDEX, config-driven rather than
forked per country. This plan covers the work still needed *here* to make that real, now that
the SDK it depends on for `ch` exists with a known, concrete API — `medindex-sdk`'s own
`docs/plan.md` covers that repo's side.

## The medindex-sdk API this plan builds against

`@icure/medindex-sdk` exports a `MedIndexClient` constructed with just `{baseUrl}` (no auth —
the standalone server is public, non-PHI reference data). It exposes `.product`, `.package`,
`.compendium`, `.interaction`, `.limitation`, `.version` resources; the two that matter for
medication lookup:

- `client.product.iterateByLabel(label, language): AsyncIterable<MedicationProductDto>` — the
  SDK already handles pagination internally (see its `pagination.ts`); callers `for await`
  directly, never touching a cursor.
- `client.package.byPharmacode(pharmacode) / .byGtin(gtin) / .byProductIds(ids)` for
  package-level detail.
- Every failure mode throws one of `MedIndexNotFoundError` / `MedIndexValidationError` /
  `MedIndexServerError` / `MedIndexNetworkError` (all extending `MedIndexError`) — there is no
  `undefined`-on-not-found convention on the SDK side.

This matters for two things PRD #3 left open (SDK didn't exist yet when it was written):
`MedIndexMedicationProvider`'s pagination adapter turns out to be trivial (the SDK already
returns a plain `AsyncIterable`), and this repo now needs to decide how `MedicationProvider`
represents errors, since `medindex-sdk` and SAM's `IccBesamv2Api` don't fail the same way.

| `MedIndexMedicationProvider` pagination | Pass the SDK's `AsyncIterable` straight through, mapping each yielded DTO to `MedicationType`                                                                                                                                                                                             | Now that the SDK's own `iterateByLabel` already hides cursor pagination, `SamMedicationProvider`'s existing `PaginatedListIterator` and `MedIndexMedicationProvider`'s adapter no longer need parallel pagination logic — only a per-item map function differs between them.                                                                                                                                                                                                                                                                                                                                           |
| `MedicationProvider` error contract     | `MedicationProvider` defines its own country-agnostic error hierarchy (`MedicationProviderError` base; `MedicationNotFoundError`, `MedicationSearchValidationError`, `MedicationProviderUnavailableError`); each concrete provider translates its backend's native errors at the boundary | Only choice that makes the "`MedicationProvider` contract tests" (PRD #3) actually meaningful — asserting identical error *behavior* across `SamMedicationProvider`/`MedIndexMedicationProvider` requires both to throw the identical *type*, not two backend-specific ones. `MedicationProviderUnavailableError` deliberately collapses medINDEX's separate `MedIndexServerError`/`MedIndexNetworkError` — a component only needs "try again later," not the exact cause, and forcing `SamMedicationProvider` to replicate a server-vs-network split its SDK may not cleanly expose would be manufactured complexity. |
| `@icure/medindex-sdk` dependency, revisited | Real npm semver range (`^0.1.4`), not `file:../medindex-sdk` | `@icure/medindex-sdk` 0.1.4 is now actually published to npm (confirmed via `npm view @icure/medindex-sdk versions`) — the "pre-publish" row above is superseded. |
| `MedicationProvider.findByLabel` shape  | Returns one unified `AsyncIterable<MedicationType>` (or an async-iterable of the grouping type) per provider, not three separate lane iterables | `MedicationSearch` today merges three SAM-specific lanes (AMP/products, VMP-group/molecules, NMP/non-medicinal) via `mergeLazySortedNamedItems`. medINDEX has no equivalent 3-bucket split — only one product stream. Baking the 3-lane shape into the country-agnostic interface would leak SAM's structure into the abstraction. `SamMedicationProvider` internally merges its 3 lanes (reusing the existing merge logic) before exposing one stream; `MedIndexMedicationProvider` just exposes its single product stream. `MedicationSearch` stops holding 3 separate iterator refs. |
| Header summary-pill genericization       | Extend the badge registry to a `placement: 'summary' \| 'detail'` concept — `MedicationCard`'s collapsed `Header` row (today hardcoded to SAM's reimbursement-category/delivery-code/prescription-code/cheap-cheapest pills) becomes registry-driven the same way the expanded infographic badges are | Discovered during implementation-planning: `Header` reads `medication.reimbursements`/`deliveryModusCode`/`cheap`/`cheapest` directly, a second BE-specific leak beyond the four infographic components plan.md originally named (`ReimbursementsContent`, `Start/EndOfCommercialisationContent`, `SupplyProblemsContent` — this also missed `DeliveryConditionsContent`/`PrescriptionConditionsContent`/`RmaProfessionalLinkContent`, all 7 infographic-elements need registry coverage, not 4). Leaving `Header` BE-specific would mean a "country-agnostic" component still hardcoding `regulatory.be` once the type redesign lands. |
| Docs staleness at plan-execution time    | `CLAUDE.md` and `CONTEXT.md`'s descriptions of file layout/dependency names had drifted from the actual code by the time implementation started | `CLAUDE.md` still describes a flat `components/`/`services/` layout, "no test suite," CRA demo-app, and a `medication-mapper/index.ts` module — none true anymore (real layout is `src/shared/` + `src/internal/`, Vitest is fully configured with 3 existing test files, demo-app runs on Vite, and SAM mapping lives inline in `medication-loader.ts`, not a dedicated module). Treat the *architecture intent* in these docs as authoritative, not literal file/module names — verify against actual source before each step. |

- [x] **Decide `MedicationProvider`'s error contract** — resolved above: its own `MedicationProviderError` hierarchy (`MedicationNotFoundError`, `MedicationSearchValidationError`, `MedicationProviderUnavailableError`); `MedIndexMedicationProvider`'s mapping from `medindex-sdk`'s errors is exact, `SamMedicationProvider`'s mapping is TBD against `@icure/api`'s actual error shape when that provider is implemented.
- [x] **Pick a test runner** — already done before this plan's execution started: Vitest is fully configured (`vitest.config.ts`, `src/testing/` helpers/fixtures, 3 existing `*.test.ts` files) — not a still-open choice.

- [x] **Task A — Redesign `MedicationType` + extract `SamMedicationProvider`, no behavior change for `be`** — country-agnostic core (`id`, `kind`, `title`, `activeIngredient`, `index`) + `regulatory: { be?; ch? }`; `MedicationProvider` interface + error hierarchy; `mapSamMedication` extracted from `medication-loader.ts`; `SamMedicationProvider` implemented; `MedicationSearch` rewired to a `medicationProvider` prop (async-iterator consumption, `enrichForPrescription`/`loadCheapAlternatives` optional methods replacing the old direct `sdk` calls). `CheapAlternatives`/`Extension`/`PrescriptionModal` got mechanical `regulatory.be.X` field-path fixes only (kept their `sdk` prop — out of scope, `be`-only prescription-sending flow). 30/30 tests green throughout, zero behavior change confirmed by diff review.
- [x] **Task B — `mapMedIndexMedication` + `MedIndexMedicationProvider`** — implemented; product+package pairing (medINDEX's `MedicationProductDto`/`MedicationPackageDto` split mirrors SAM's AMP/AMPP), `de`/`fr`/`it` language fallback (default `de`), price-type preference `PPUB → PPHA → PEXF`.
- [x] **Task C — Regulatory badge registry, `summary` + `detail` placements** — implemented (`registerRegulatoryBadge`/`getRegulatoryBadges`/`RegulatoryBadges` renderer); all 7 original infographic-elements plus the 3 previously-inline `Header` tooltips converted to registered `be` badges; `ch` badges authored (`swissmedicCategory`, `narcotic`, `coldChain`, price). **Known residual gap** (found during Task H's live verification, not originally in scope): `MedicationCard`'s expanded `Extension` panel (the full-detail view below the header, distinct from the compact `MedicationInfographics` tooltips) still reads `regulatory.be.*` directly and isn't registry-driven — a `ch` medication's expanded panel shows an empty/`be`-labeled block instead of its own content. Not fixed this phase; needs its own follow-up (likely a third badge placement, e.g. `'expanded'`, since `Extension`'s always-visible layout differs from the icon+tooltip shape `summary`/`detail` badges assume).
- [x] **Task D — Country config resolver** — `createMedicationProvider({country, ...})` factory implemented (`be`/`ch` only, no `fr` branch — nothing to construct yet). Badge resolution needed no explicit country switch in the end: `RegulatoryBadges` already renders whatever's registered for whichever `regulatory.<country>` keys are actually populated on a given medication.
- [x] **Task E — `MedicationProvider` contract tests** — implemented (`runMedicationProviderContractTests`, run against both providers). Found and fixed a real bug: `MedIndexMedicationProvider.findByLabel` leaked the SDK's raw `MedIndexValidationError` for short labels instead of translating it (the `iterateByLabel(...)` call was outside the provider's try/catch) — fixed, since `ch` is new code with no prior behavior to preserve. Also documented (not fixed, by design/asymmetry, not a bug): `SamMedicationProvider` does no client-side short-label validation of its own — that guard only lives in `MedicationSearch`'s UI.
- [x] **Task F — Per-country mapper tests** — implemented, 34 tests. **Found a genuine pre-existing bug, not fixed** (predates this refactor — present in the original inline `medication-loader.ts` mapping before Task A even started, so fixing it would be a `be` behavior change outside this refactor's "zero behavior change" constraint): `mapSamMedication`'s reimbursement-validity filter (`reimbursement.from && (!reimbursement.to || reimbursement.to > now)`) never checks `now >= from` — a reimbursement whose validity window hasn't started yet but has an open-ended/future `to` is incorrectly treated as currently valid. Documented with a dedicated regression test; needs a maintainer decision on a separate fix/release.
- [x] **Task G — Regression-check the `be` demo-app flow** — code-level regression check complete (diff review + the full test suite, byte-faithful to pre-refactor behavior); live browser check confirmed the `be` section boots, gates on certificate validity, and fails gracefully with invalid credentials without crashing the app (observed incidentally during Task H's live verification). **Not verified**: an actual live SAM search against real data — this repo has no test/nightly SAM credentials available in this environment; would need real `cockpit.icure.dev` credentials from a maintainer to close out fully.
- [x] **Task H — Wire a `ch` example into `demo-app`** — implemented and verified live end-to-end against the real local medINDEX server (`http://localhost:8080/rest/v2/medindex`): real search results, `regulatory.ch` fields displayed, and both `narcotic`/`swissmedicCategory` detail badges confirmed rendering in the browser. Found and worked around (in demo-app only, no library/SDK change) a real `@icure/medindex-sdk@0.1.4` bug: `MedIndexHttpClient` defaults to the bare global `fetch`, which browsers reject when invoked detached from `window` — worked around by passing `fetch: window.fetch.bind(window)` explicitly when constructing `MedIndexClient` in `App.tsx`.
- [ ] **Task I — Make `Extension` registry-driven** — `MedicationCard`'s expanded detail panel (`internal/components/medication-elements/MedicationCard/medication-card-elements/Extension/index.tsx`) still reads `regulatory.be.*` directly and renders `ReimbursementsContent`/`PrescriptionConditionsContent`/`DeliveryConditionsContent`/`SupplyProblemsContent`/`Start-EndOfCommercialisationContent` unconditionally for `be`, unlike `MedicationInfographics` — found during Task H's live `ch` verification (a `ch` medication's expanded panel currently renders an empty, `be`-labeled block instead of its own content). Likely needs a third badge placement (e.g. `'expanded'`) alongside `'summary'`/`'detail'`, since `Extension`'s always-visible full-content layout doesn't fit the icon+tooltip shape the existing two placements assume. `ch` badges for this placement (VMP-equivalent composition detail, links, etc.) would need authoring too.
- [ ] **Task J — Fix `mapSamMedication`'s reimbursement-window bug** — `dmpp?.reimbursements?.find((r) => r.from && (!r.to || r.to > now))` never checks `now >= r.from`, so a reimbursement whose validity window hasn't started yet (future `from`) but has an open-ended/future `to` is incorrectly treated as currently valid. Pre-existing — present in the original inline `medication-loader.ts` mapping before this phase's refactor started, so it predates `MedIndexMedicationProvider`/`SamMedicationProvider` entirely. Documented with a regression test in `map-sam-medication.test.ts` asserting today's actual (buggy) behavior; flip that assertion once fixed. Needs a maintainer decision first since fixing it is a `be` production-behavior change, not purely a refactor.
- [ ] **Task K — Fix `@icure/medindex-sdk`'s browser-`fetch` bug** (separate repo, `../medindex-sdk`) — `MedIndexHttpClient` defaults to the bare global `fetch` reference (`config.fetch ?? fetch`), which browsers reject when invoked detached from `window` (`TypeError: Failed to execute 'fetch' on 'Window': Illegal invocation`). Found during Task H's live verification; worked around in this repo's demo-app only (`new MedIndexClient({ ..., fetch: window.fetch.bind(window) })`), so every other consumer of `@icure/medindex-sdk` hits this until the SDK itself binds `fetch` to `globalThis`/`window` by default.
- `fr`: no implementation this phase — gap analysis content lives in PRD #3; out of scope here (see PRD #3's Out of Scope section).
